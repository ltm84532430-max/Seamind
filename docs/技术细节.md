# Markmap & Seamind 项目技术实现与对接文档

本技术文档系统性地概括了本项目（Markmap 渲染核心库及 Seamind 桌面端工作台）的系统架构、渲染引擎实现算法、前后端 IPC 通信协议、数据结构标准与工程对接指引，供研发团队对接、二次开发与架构审计使用。

---

## 一、 系统架构全景

项目采用 **Monorepo** 多包工程结构，底层为高解耦的跨平台思维导图解析与 SVG 渲染引擎，上层为基于 **Tauri 2 (Rust + React 19 + TypeScript)** 的高性能桌面工作台。

└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Tauri IPC (JSON-RPC)

│  • PTY 终端会话运行时 (pty)   • 增量索引与本地缓存     • LLM 兼容客户端 │

## 三、 渲染引擎关键技术实现

渲染核心实现位于 [`packages/markmap-view/src/view.ts`](file:///%USERPROFILE%/markmap/packages/markmap-view/src/view.ts)，以下为关键算法机制：

### 1. 层次排版与动态测量机制
- **测量流程**：Markmap 将每个节点放入 SVG `<foreignObject>` 内的 `xhtml:div` 容器中。
- **自动布局**：调用 `_relayout()` 读取 DOM 的 `scrollWidth` 与 `scrollHeight`，并将尺寸注入 `d3-flextree` 计算每个节点的精确层级坐标 $(x, y)$。
- **自适应重排**：利用 `ResizeObserver` 监听节点容器，一旦内容发生异步变更（如图片加载、样式微调），自动防抖触发 `renderData()` 触发流体动画重排。

### 2. 平滑圆角正交连线算法 (`rounded-orthogonal`)
位于 [`packages/markmap-view/src/view.ts`](file:///%USERPROFILE%/markmap/packages/markmap-view/src/view.ts#L42-L85)：
- **几何模型**：连线由水平引出段、垂直过渡段与水平接入段构成，拐角处通过**二次贝塞尔曲线 (`Q cx,cy x,y`)** 进行平滑倒角。
- **倒角半径约束**：引入 `effectiveR = Math.min(radius, Math.abs(dx) / 2, Math.abs(dy) / 2)`，避免分支极其靠近时弧度溢出破损。
- **中心针脚锚定 (`linkAnchor: 'center'`)**：
  连线起点不再挂靠在卡片底部的下划线上，而是直接锚定在父卡片的几何中心水平右端/左端 $(x \pm \text{width}, y + \text{height}/2)$，形成规整的现代工整卡片流向。

### 3. 双向对称平衡分支算法 (`direction: 'both'`)
- 根节点的一级子分支自动拆分为左右两翼。
- **子树加权贪心平衡**：算法递归统计各分支的叶子节点总量（子树权重 `weight`），将最大权重的分支交替分配至左右两侧，确保双向展开时左右画布重心均衡、不出现单侧过载。

### 4. 视觉主题体系与折叠标记
在 [`apps/desktop/src/styles.css`](file:///%USERPROFILE%/markmap/apps/desktop/src/styles.css) 中实现三套高颜值预设：
- `gray`（灰阶层级）：纯净白底灰阶，强调几何次序与层级反差。
- `warm`（暖色分支）：用大地色系多色谱区分一级子树。
- `cards`（结构卡片）：全层级包裹圆角药丸卡片，微投影悬浮质感。
- **折叠胶囊**：收起子树时，节点右侧显示带数字计数的折叠胶囊 badge（如 `+3`），点击平滑展开。

## 四、 桌面端工作台架构与交互实现

### 1. 0 缝隙一体化栅格对接
工作台布局抛弃了传统浮动弹窗和厚重边距，在 [`apps/desktop/src/styles.css`](file:///%USERPROFILE%/markmap/apps/desktop/src/styles.css) 中采用 CSS 自定义属性驱动的网格系统：
```css
.workspace {
  --col-library: 240px;
  --col-source: minmax(280px, 32%);
  --col-ai: 320px;
  display: grid;
  grid-template-columns: var(--col-library) var(--col-source) minmax(0, 1fr) var(--col-ai);
  padding: 0;
  gap: 0;
}
```
- **四列紧密贴合**：
  1. `[00 / LIBRARY]` 本地文件库管理栏
  2. `[01 / SOURCE]` Markdown 源文本编辑器
  3. `[02 / CANVAS]` 思维导图无限画布
  4. `[03 / CO-PILOT]` LLM 智能构图助手
- **极简边界**：四栏之间使用统一 `1px solid var(--line)` 细线分割，顶栏统一 `52px` 高度，保证整体对齐线严密平直。

### 2. 独立折叠与状态持久化
- 三个侧边栏均支持折叠至 `42px` 极简竖条（显示纵向文字徽章），画布自适应填满剩余空间。
- 折叠状态、主题模式与导图样式均持久化保存在浏览器安全 LocalStorage 中：
  - `seamind.theme.v1`: `'light'` | `'dark'`
  - `seamind.map-style.v1`: `'gray'` | `'warm'` | `'cards'`
  - `seamind.ai-collapsed.v1`: `'true'` | `'false'`
  - `markmap.desktop.provider-settings.v1`: `{ baseUrl, model }`

## 五、 Tauri 原生后端 IPC 接口对接规范

Rust 原生服务位于 [`apps/desktop/src-tauri/src/lib.rs`](file:///%USERPROFILE%/markmap/apps/desktop/src-tauri/src/lib.rs)，前端通过 `@tauri-apps/api/core` 的 `invoke()` 进行调用：

### 1. 凭据与模型管理接口

| 命令名 (Command) | 入参 (Payload) | 返回值 (Return) | 描述 |
| :--- | :--- | :--- | :--- |
| `has_api_key` | `{}` | `boolean` | 探测 Windows 凭据管理器中是否存在已存凭据 |
| `save_api_key` | `{ apiKey: string }` | `void` | 将 API Key 加密保存至 Windows Credential Manager |
| `delete_api_key` | `{}` | `void` | 从系统凭据管理器中安全注销 API Key |
| `generate_mindmap` | `{ baseUrl: string, model: string, prompt: string }` | `string` (Markdown) | 请求 OpenAI 兼容接口，解析生成标准大纲 Markdown |

### 2. 本地文件库存储与监控接口

| 命令名 (Command) | 入参 (Payload) | 返回值 (Return) | 描述 |
| :--- | :--- | :--- | :--- |
| `library_status` | `{}` | `LibrarySnapshot` | 获取文件库当前根路径、分类及文档列表 |
| `set_library_root` | `{ path: string }` | `LibrarySnapshot` | 设定文件库工作目录并启动文件监听器 |
| `search_library` | `{ query: string, category: string \| null }` | `MapDocument[]` | 检索库内思维导图文档（支持分类过滤） |
| `open_document` | `{ relativePath: string }` | `OpenedDocument` | 读取并加载指定 Markdown 导图草稿 |
| `save_document` | `SaveDocumentInput` | `MapDocument` | 将导图保存入库（自动维护 Frontmatter 元数据） |
| `delete_document` | `{ relativePath: string }` | `void` | 删除指定导图文件并更新索引 |
| `create_category` | `{ name: string }` | `LibrarySnapshot` | 在文件库内新建多级分类物理文件夹 |

### 3. EPUB 电子书大纲导入接口

| 命令名 (Command) | 入参 (Payload) | 返回值 (Return) | 描述 |
| :--- | :--- | :--- | :--- |
| `import_epub_toc` | `{ path: string }` | `EpubOutlineResult` | 仅解压并解析 EPUB 的 `toc.ncx` / `nav.xhtml`，秒级生成目录思维导图 |

### 4. 终端会话控制接口 (PTY Session)

| 命令名 (Command) | 入参 (Payload) | 返回值 (Return) | 描述 |
| :--- | :--- | :--- | :--- |
| `terminal_start` | `{ cols: number, rows: number }` | `string` (sessionId) | 启动系统交互式伪终端 (PowerShell/Cmd) |
| `terminal_write` | `{ sessionId: string, data: string }` | `void` | 向终端标准输入流写入命令数据 |
| `terminal_resize` | `{ sessionId: string, cols: number, rows: number }` | `void` | 同步窗口尺寸变动至 PTY |
| `terminal_close` | `{ sessionId: string }` | `void` | 销毁终端进程与缓冲区 |

## 六、 核心数据模型定义

### 1. 思维导图节点模型 (`IPureNode`)
```typescript
export interface IPureNode {
  /** 节点展示的 HTML/SVG/文本内容 */
  content: string;
  /** 子节点列表 */
  children: IPureNode[];
  /** 携带的扩展载荷（如折叠状态、自定义属性） */
  payload?: {
    fold?: number; // 0: 展开, 1: 折叠, 2: 递归折叠
    [key: string]: unknown;
  };
}
```

### 2. 文件库元数据模型 (`MapDocument`)
```typescript
export interface MapDocument {
  id: string;
  relativePath: string;
  title: string;
  category: string;
  mapType: string;
  tags: string[];
  updatedAt: string;
  charCount: number;
}
```

## 七、 本地构建与验证指引

### 1. 环境准备
- **Node.js**: `>= 18.0.0`
- **Rust Toolchain**: `stable` (带有 `cargo` 与 `rustc`)
- **包管理器**: `pnpm` (工作区配置依赖 `pnpm-workspace.yaml`)

### 2. 关键指令
```bash
# 1. 运行核心库单元测试 (Vitest)
npx vitest run

# 2. 编译打包桌面端 Web 资源 (Vite)
cd apps/desktop
npx vite build

# 3. 启动桌面端本地调试 (Tauri Dev)
cd apps/desktop
pnpm tauri dev
```

> [!TIP]
> 桌面端打包时已通过 `vite.config.ts` 中的 `css.postcss.plugins = []` 隔离了主工程与子应用的 PostCSS 查找链，确保跨平台构建过程稳定可控。

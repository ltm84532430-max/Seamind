# 播放器页面：订阅、动态、收藏与课程

顶栏的“播放器”是和“导图”“电子书”并列的第三个工作区，用来在本机管理要看的 YouTube 视频：订阅频道、看新视频、收藏、把播放列表当课程来学，并记住每个视频看到哪里。不需要登录 Google 账号，数据都在本机。

设计参考了开源应用 NewPipe 处理订阅的办法（本机订阅、按需检查更新、观看状态规则）；NewPipe 是 GPL-3.0，这里只借鉴思路，没有复制或链接它的代码。

## 用法

- **粘贴链接**：左上角的输入框接受视频、播放列表、频道的链接，`@名称`，或 24 位频道 ID。视频直接播放（链接里的 `t=` 会作为起点），频道和播放列表先打开它们的页面。
- **订阅**：打开频道页后点“订阅”。也可以点“导入订阅”，选 NewPipe 导出的 JSON、Google Takeout 的 `subscriptions.csv`（或 JSON）、或 OPML。导入只添加，不删除已有订阅。
- **动态**：所有订阅的新视频，最新在前。打开动态时自动检查需要更新的频道（见下），也可以点“更新”检查全部。个别频道失败不影响其他频道，列表上方会列出失败的频道并可重试。
- **收藏 / 稍后看**：每行右侧的星标和钟表；“✓”手动标记已看或未看。
- **课程**：打开一个 YouTube 播放列表，点“保存为课程”。课程按列表顺序排，侧栏显示“已看完/总数”，“继续学习”从第一个没看完的视频开始，“同步列表”重新读取播放列表加入新视频。
- **播放**：点视频进入播放页，右侧是它所在列表的队列，视频结束后自动播放下一个（可在设置里关）。位置每 10 秒和暂停、结束、离开时记一次；再次打开从上次位置继续（取整秒，内嵌播放器的起点参数不接受小数）。支持 0.75–2 倍速。官方内嵌播放器 12 秒内没有开始播放时，页面会提示改用下面的“内置播放器”或“本地解析”：YouTube 对部分视频会在画面里要求登录验证（对当前网络的风控），播放器接口对此不报错，页面只能从“没开始播放”看出来。切到别的工作区时默认暂停，设置里可以改成后台继续播（边听边整理导图）。
- **设置**：检查间隔、自动播放、切换工作区是否暂停、动态是否隐藏已看；导出订阅（NewPipe 格式，NewPipe 也能导入）、导出和恢复全部数据、清空历史。

## 规则

- **看完**：剩余不足 60 秒且已播放至少四分之三，算看完，下次从头开始；也可以手动标记。位置超过 5 秒（或短视频超过四分之一）才会保存，一次很短的打开不会覆盖之前的位置。（NewPipe 的规则。）
- **检查更新**：只检查“从没检查过、上次失败、或距上次检查超过设定间隔”的频道，同时 3 个，每 50 个频道停 6–12 秒，顺序打乱。保留最近 13 周的视频，被收藏、看过或在课程里的不清理。
- **不含 Shorts**：动态用频道的“长视频”播放列表（`UULF…`，把频道 ID 的 `UC` 换成 `UULF`）的 RSS，里面没有 Shorts；频道没有这个播放列表（404）时改用频道自己的 RSS，并按链接里的 `/shorts/` 过滤。RSS 带精确发布时间，不带时长；频道页和播放列表给时长，但日期只有“3 天前”这样的近似值，界面标“约”。
- **没有日期的视频不进动态**：保存为课程的视频没有发布日期，只出现在课程里，不会当成新视频刷到动态顶部。

## 数据

保存在应用本地数据目录的 `player.sqlite3`（SQLite，WAL 模式，首次打开时建表）：频道、视频缓存、观看状态、历史、播放列表（收藏和稍后看是两个内置列表）、设置。调试版可用环境变量 `SEAMIND_PLAYER_DB` 指定另一个文件，检查时不碰用户自己的数据。

导出的备份是一个 JSON 文件，恢复时合并：以更新时间较新的观看状态为准，不会清空现有数据。

## 网络与安全

- 频道页、播放列表、`@名称` 解析走页面里的 YouTube.js，经本地回环代理（和内置播放器同一条路径，用户配置的代理对它生效）。它们都不请求播放地址，所以不会遇到“确认你不是机器人”的检查，那只会出现在播放时。
- 频道的更新（RSS）和视频标题（oEmbed）由 Rust 端请求。
- 网络不稳时（比如经代理偶尔连接被中断或返回 502/503/504），这些只读请求会自动再试：页面里的 YouTube.js 请求最多重试 2 次（间隔 0.6、1.5 秒），Rust 端的 RSS 和 oEmbed 请求同样重试 2 次（0.7、1.5 秒）；超时和被取消的请求不重试。缩略图加载失败也会再请求两次。连接很慢时（一个挂起的连接 10 秒才放弃），频道页、播放列表和粘贴框会在 8 秒后提示“连接 YouTube 比较慢，正在重试”。
- 内容安全策略的 `img-src` 增加了 `yt3.googleusercontent.com` 和 `yt3.ggpht.com`（频道头像）；缩略图用 `i.ytimg.com`。没有头像的频道显示首字圆标。

## 代码位置

- 前端 `apps/desktop/src/player/`
  - 界面：`PlayerWorkspace.tsx`（状态、导航、播放队列）、`Sidebar.tsx`、`FeedView.tsx`、`CollectionView.tsx`（收藏、稍后看、历史、课程）、`ChannelView.tsx`、`RemotePlaylistView.tsx`、`WatchView.tsx`、`PlayerDialogs.tsx`、`VideoRow.tsx`、`VideoList.tsx`、`player-workspace.css`。
  - 不依赖界面的规则（有单元测试）：`video-links.ts`（识别粘贴的链接）、`import-subscriptions.ts`（四种订阅文件）、`feed-manager.ts`（检查更新的节奏）、`watch-state.ts`、`youtube-mapping.ts`（YouTube.js 的结果转成数据库输入）、`queue.ts`、`format.ts`、`retry-fetch.ts`（失败重试）。
  - 接后端和 YouTube：`player-api.ts`（`player_*` 命令）、`youtube-data.ts`。
- 播放器本体 `apps/desktop/src/YouTubePlayerPanel.tsx`：从原来的弹窗里拆出，弹窗（`YouTubePlayerDialog.tsx`）和播放页共用，包括官方内嵌、内置播放器和 yt-dlp/mpv 三种方式及回退。播放页里它不带标题栏和关闭按钮，内嵌播放器自动开始，并通过 `onProgress`、`onEnded`、`onHandle`（读写位置和倍速）把播放状态交给页面。
- 后端 `src-tauri/src/player_store.rs`（数据库和全部规则）、`player.rs`（Tauri 命令、频道 RSS、oEmbed）。
- 测试：`apps/desktop/test/player-*.test.ts`，以及两个 Rust 模块里的单元测试。

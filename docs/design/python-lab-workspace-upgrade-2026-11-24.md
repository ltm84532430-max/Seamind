# Seamind Python Lab 工作区升级方案

日期：2026-11-24。范围：Python Lab 的布局、实验本交互、多文档与多窗口体验。本轮交付为设计方案与三张视觉概念稿，尚未修改运行中的 Lab 前端。

## 目标与判断

让用户完成“打开两个实验本 → 对照编辑 → 分别运行 → 查看结果 → 保存并恢复布局”，每一步都能明确当前文档、执行内核和保存状态。

当前界面的低效来自信息层级和文档模型，不只是配色。截图中一个短代码格下面出现大面积留白，也与文档内容较少有关；设计不应通过默认展开无关面板填满空间。应在任务需要时提供全宽编辑、分屏和可固定输出。

保留 Seamind 深色、扁平、细分隔线的视觉基础。重用现有 CodeMirror、单元格、输出和运行接口。当前产品是支持 Pyodide / 本地 Python 的实验本，不应把视觉升级宣传成已经具有完整 Jupyter 服务协议兼容性。

## 当前证据与需要修正的行为

| 证据 | 影响 | 修正方向 |
| --- | --- | --- |
| 用户截图：全局导航、终端标签、实验本工具栏叠放；Python Lab 标签与文档名分属两层 | 用户需要反复确认当前对象，正文起点过低 | 终端与 Agent 保留会话标签；Lab 直接用文档名作为标签，不再叠加泛称 Python Lab |
| 用户截图与 CSS：正文居中，`.codelab-paper-column` 最终上限为 1080px | 宽屏两侧留白，横向空间不能主动用于比较 | 提供标准阅读宽度与全宽两档；分屏时正文自适应所在面板 |
| `withActiveLabHandle` 优先使用活动或已有 Lab；`handleOpenSavedCodeFile` 调用它加载文件 | 文件列表的默认路径倾向复用 Lab，没有清楚表达第二份文档的打开位置 | 显式提供当前预览、新标签、右侧分屏、独立窗口四种行为 |
| `createSpecialTab`、分屏模式和 `WebviewWindow` 已存在 | 无需从零搭建整个多窗口系统 | 补齐文档身份、会话路由、状态恢复和直达入口 |
| 独立窗口 URL 传递 cwd、kind、language、theme，没有当前文档 ID | 弹出当前文档所需的信息不完整 | 用文档 ID 和已保存草稿定位内容，窗口创建后完成握手 |
| `activeLabInfo` 是一个共享状态；每个 Lab 回调都写入它 | 多文档时侧栏高亮和文档状态有被其他 Lab 更新覆盖的风险，尚未做运行复现 | 按 tabId 存放文档状态，再按当前焦点读取 |
| `openStandaloneTerminalWindow` 在 300ms 后可能提前返回成功 | UI 的成功提示可能早于实际窗口就绪，尚未验证是否为用户此次失败原因 | 创建事件与文档加载握手都成功才提示；超时保留可重试错误 |
| 大型输出在 localStorage 保存前可能被省略或截断 | 刷新后不能把缺失输出误显示为当前完整计算结果 | 输出单独持久化，显示来源、运行时刻与过期状态 |

说明：以上代码路径已查阅当前工作区；用户截图支持视觉判断。双开失败的具体运行原因、键盘可达性和性能数据尚未做交互审计。

| 文档工具栏 | 一行显示运行当前格、运行全部、添加单元格、内核 | 运行中原位置出现停止；源码、导入导出和重命名移入更多菜单；空间不足时按优先级收起文字 |

| 代码单元格 | 36px 执行编号栏，代码 14px / 行高约 21px | 选中格有细强调线；移动、复制、删除在悬停、键盘聚焦或更多菜单中可达；执行按钮不重复占据多层工具栏 |
| 插入与重排 | 格间有轻量插入线，末尾保留“添加单元格” | 支持代码 / Markdown；拖拽排序，同时提供键盘移动和菜单操作 |
| 输出 | 默认就地展示；长输出内部滚动，图表支持放大 | 可固定到右侧；固定输出标注对应文档与单元格；代码修改后旧输出显示“需要重新运行” |
| 数据与变量 | 默认折叠，主动查看时展开 | 列表显示名称、类型、形状与简短预览；大数组 / DataFrame 分页或按需读取，不一次性序列化全部内容 |

| 保存与反馈 | 文档级显示保存中、已保存、失败 | 失败保留草稿并可重试；关闭脏文档提供保存、保留草稿或放弃选择；后台文档运行不抢焦点 |

## 多标签、分屏与独立窗口的完整规则

### 不同实验本

- 每份文档有稳定 `documentId`；每个可见视图有 `viewId`；每个执行会话有 `kernelId`。
- 打开 A 后再打开 B，A 的代码、输出、滚动位置、选中格和未保存状态均保留。
- A、B 默认独立内核，分别运行、停止、重启；A 中的变量不应意外出现在 B。
- 分屏是同一个窗口里的两个编辑组；独立窗口是另一个系统窗口。按钮和菜单要直接写出这两种不同结果。
- 同屏最多先提供两个主编辑组，窗口宽度不足时切回标签。现有三分屏 / 四分屏可留在高级布局菜单，避免成为默认负担。

### 同一实验本的第二视图

- 默认激活已打开文档；选择“新建同步视图”时才创建第二视图。
- 同步视图共用文档模型和内核，并清楚标记“同步视图 · 共用 PY-01”。每个视图保留自己的滚动和选中状态。
- 想独立修改或独立执行时，提供“复制实验本”，生成新文档和新内核。
- 不允许两个独立 localStorage 副本静默覆盖同一文档。跨窗口使用统一保存服务、revision 检查和冲突恢复；不能只靠页面卸载前保存。

### 弹出与回收

- “移到独立窗口”先保存当前草稿，传递 documentId / viewId，并在目标窗口加载完成后才移除原视图。
- “新窗口打开副本”另存文档，行为与移动不同。
- 用户关闭最后一个视图时明确说明是否保留运行会话；关闭一个同步视图不能直接杀死其他视图共用的内核。
- 提供“返回主窗口”，恢复到原编辑组或新编辑组。
- 初期允许移动时重新建立执行会话，但必须明确提示变量状态重置。若要无缝保留 Pyodide 状态，需要把 Worker 生命周期移交给跨视图会话宿主；普通页面 Worker 不能直接随视图跨 WebView 转移。

## 功能扩展与实施次序

### P0：让基础工作流可靠且清楚

1. 精简 Lab 标签和工具栏；左栏重组；正文提供标准 / 全宽；控制台默认折叠。
2. 文档标签、右侧打开、独立窗口入口；用明确 documentId 加载，不再按语言随意复用。
3. tabId → 文档状态映射；焦点、运行按钮、变量、控制台严格指向当前会话。
4. 草稿保护、保存失败反馈、跨窗口 revision 冲突处理、窗口创建握手。
5. 恢复打开文档、分屏比例、面板显隐和滚动位置。恢复布局不等于恢复内核中的变量；后者需真实会话仍存在。

验收：A、B 同屏运行；各自 `x` 的值互不影响；A 未保存时打开 B 不丢代码；弹出 B 打开正确内容；关闭 / 刷新能恢复草稿和布局；窗口失败不能显示“已打开”；后台输出不写进另一份文档。

### P1：改善计算与检查效率

1. 固定输出到右侧、图表独立放大、输出折叠、长日志限高。
2. 变量和 DataFrame 按需预览；控制台连接当前内核；执行队列显示运行 / 待运行 / 已停止。
3. 运行至当前格、运行当前格以下、失败定位、耗时与错误堆栈到源码跳转。
4. 单元格跨实验本复制、Markdown 大纲、快捷键帮助、命令面板。
5. 大型输出改为异步存储并关联文档 revision，避免同步写入阻塞。

验收：固定输出能追踪正确 cellId；修改源码后旧结果明确过期；变量面板不触发全量大型对象传输；重启内核后变量和执行状态更新；100 格实验本编辑、切换和滚动不因一次性挂载全部编辑器而明显停顿。性能阈值用真实设备测量后设置。

### P2：增强 Seamind 的学习闭环

1. 电子书 / PDF 选中代码发送到指定实验本，保留书籍、章节 / 页码和原文定位。
2. 实验结论发送到知识库或思维导图，携带代码格、输出与来源引用。
3. 实验模板、执行历史、版本比较和参数快照，帮助复现实验。
4. 如需完整外部 Jupyter 生态，再单独评估 Jupyter Server 连接、内核协议、环境发现与凭据管理。不要把它作为这次样式更新的隐含依赖。

## 布局与视觉参数

- 保留深色工作台：基础背景 `#151B20`，编辑区 `#1B232A`，分隔线 `#35424C`，正文 `#DFE8ED`，次要文字 `#9EAEB9`，主强调 `#9FCBB8`。这些为设计候选值，实施时检查实际对比度。
- 无渐变、玻璃和装饰阴影；边角约 0–4px；使用既有图标组件与统一的 16px 线性图标。
- UI 字号 13–14px；编辑器 14px；不靠降低字号容纳所有功能。
- 完整桌面范围内：标签栏约 36–40px，文档工具栏约 40px，状态栏约 24px；沿用全局导航高度。
- 主区可用宽度约 1120px 以上可显示双实验本，每组建议至少 520px。再窄则收起左栏，仍不足时回到单组标签。独立窗口可单独缩放。
- 所有悬停操作也支持键盘聚焦；选中、运行和错误状态同时使用文字 / 图标，不能只依赖颜色。
- 图中的代码、图表和运行时间为展示数据。最终实现以真实执行结果为准，不能写死在产品中。

## 推荐技术改动位置

- `apps/desktop/src/terminal/TerminalWorkspace.tsx`：文档打开路由、编辑组、焦点和按 tabId 的状态。
- `apps/desktop/src/terminal/TerminalCodeLabView.tsx`：拆分文档状态、视图状态与运行会话；单元格、输出及面板交互。
- `apps/desktop/src/terminal/terminal-window.ts`：文档参数、窗口就绪握手、弹出和回收。
- `apps/desktop/src/terminal/terminal-types.ts`：补齐 documentId / viewId / kernelId 与布局模型。
- `apps/desktop/src/terminal/terminal-codelab-model.ts`：文档版本、草稿和输出存储契约。
- `apps/desktop/src/terminal/terminal-workspace.css`：整理最终生效的 Lab 样式，实施时逐步移除重复覆盖，而不是继续堆叠覆盖规则。
